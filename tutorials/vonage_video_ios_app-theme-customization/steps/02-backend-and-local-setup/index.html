Backend & Local App Setup

The iOS app doesn't have a backend of its own — it talks to the same Node.js server the Vonage Video React App uses, running on port 3345. In this step you will start that backend here in the Codespace, expose its port publicly, then clone the iOS app to your own Mac and run it in Xcode against that public URL.

Configure Backend Credentials

Section titled “Configure Backend Credentials”

Open a terminal inside the Codespace by clicking the hamburger menu (☰) in the top-left corner, then selecting Terminal → New Terminal. The cloned repo lives under project/, so run all commands below from there:

Replace the placeholder values in backend/.env:

VariableWhere to find it
VONAGE_APP_IDVonage Dashboard → Your Applications → the app you created for this project
VONAGE_PRIVATE_KEYThe private.key file downloaded when you created the Vonage Application — paste its full contents here

Caution

Never commit backend/.env to source control. The repo's .gitignore already excludes it, but double-check before pushing.

Make the Port Public

Section titled “Make the Port Public”

When the server starts, a notification dialog will appear in the bottom-right corner of the Codespace asking whether to make port 3345 publicly accessible. Click "Make Public".

If you miss the dialog, you can do this manually:

  1. Click the Ports tab at the bottom of the Codespace.

  2. Right-click on port 3345 → Port Visibility → Public.

Caution

The port must be public — otherwise the iOS app running on your local machine cannot reach it.

Copy the forwarded address for port 3345 from the Ports tab. You'll use it as BASE_API_URL in the next section:

Generate the Signing Configuration

Section titled “Generate the Signing Configuration”

Tuist also requires a generated signing configuration file before it can generate the Xcode project — even if you only plan to run on the Simulator. Still from VERA/, export the following environment variables, then run the signing config generator script:

The script writes Config/Signing.xcconfig.

VariableWhere to find it
DEVELOPMENT_TEAMApple Developer Portal → Certificates, Identifiers & Profiles → Membership → Team ID
MARKETING_VERSIONThe app version number you want to build, e.g. 1.1
CURRENT_PROJECT_VERSIONThe build number, e.g. 1

Caution

If you skip this step, tuist generate fails with:

Export the three variables above and re-run ./Scripts/regenerateSigningConfig.sh from VERA/, then try tuist generate again.

Generate the Xcode Project and Run It

Section titled “Generate the Xcode Project and Run It”

Still from VERA/, generate the Xcode project with Tuist and open it:

  1. In Xcode's scheme selector (top toolbar), choose the VERA scheme.

  2. Next to the scheme, choose a Simulator destination — for example iPhone 17.

  3. Press Cmd+R (or click the ▶️ Run button) to build and launch the app.

The app should launch in the Simulator and be able to reach your Codespace's backend. If you see a network error on launch, double-check that port 3345 is still public and that BASE_API_URL matches the forwarded address exactly.

Tip

You already set DEVELOPMENT_TEAM when generating the signing configuration above, so the Simulator should just work. Running on a physical device instead requires selecting your device and a valid signing team in Xcode's Signing & Capabilities tab. This is optional — the Simulator is enough to complete this tutorial.

With the backend running and the app built and running locally, you're ready to start customizing the theme.
